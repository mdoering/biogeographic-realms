= Global biogeographic realms from GBIF occurrences

An attempt to divide the whole globe, land and sea, into large non-overlapping realms from GBIF occurrence records alone,
defined by endemism at species, genus and family level, and to test how well existing schemes hold up against the result.

This is a scientific analysis, not a gazetteer. See link:docs/design.md[the design] for the method, and
link:DECISIONS.md[the decision log] for every change to it.

== Setup

Requires Python 3.13 and https://docs.astral.sh/uv/[uv].

[source,bash]
----
uv sync
uv run pytest
----

== Preparing the GBIF download

[source,bash]
----
uv run python scripts/check_release.py   # which COL release GBIF production uses
uv run python scripts/test_patterns.py   # sample real records per text term
uv run python scripts/write_queries.py   # generate and validate queries/, submitting nothing
uv run python scripts/fetch_reference.py # COL, WCVP, WRiMS, GRIIS, gazetteers, coastline, Natural Earth admin-1, the TDWG level 3 polygons (WGSRPD, no stated licence, see DECISIONS.md) and ISEA3H grids into data/reference, each licence noted in manifest.json where it was found
uv run python scripts/request_exports.py # list the ChecklistBank exports fetch_reference.py found missing (or, with --griis-extended, the GRIIS lists with no extended export); --submit asks production for them with your account
uv run python scripts/check_reference.py # rank coverage, and what WCVP's empty value means
uv run python -I scripts/check_natives.py # join WCVP, GRIIS and WRiMS to COL ids by name and print each source's match rate (matched, ambiguous, unmatched, by names and by rows); asks GBIF's match API for the names of any source with over 10% unmatched, saves the placed ones to data/reference/gbif_fallback.parquet with the COL release in its metadata (load_references refuses it for another release), then loads References (about 16 GB, 1 minute) and writes results/natives.json, which also says what each GRIIS list holds by its own establishment means (`griis_means`: the entries that are introduced, native, uncertain or have no value, for the lists with a distribution table, and the lists with none) and how many cells the sub-national lists take. --no-references skips the load
uv run python scripts/check_grid.py      # ISEA3H resolutions 5 to 7: cells, neighbours, area and land, and the median cell area
uv run python scripts/write_split.py     # freeze the family split for COL 315557 into data/split and print its hash
uv run python -I scripts/check_columns.py data/gbif/<key>.zip # a Denmark SQL download: COL's status values, accepted species and cell codes against the grids
uv run python -I scripts/ingest.py data/gbif/<key>.zip --resolution 6 # stream a SQL download into Parquet in data/gbif/<key>/, check it and write results/pilot/res6/qa.json, exiting non-zero if a pass mark fails. A cell code of the download that the grid doesn't have is mapped to the one cell with the same 2-digit code within 5 km of its centre, if the next such cell is more than 3 times as far (GBIF's code and the grid file's id of a few cells differ by up to 2.3 km at resolution 7); rows that then have the same species, country, cell and part are merged (counts add up, distinct counts take the larger), and the script prints every remap (code, target, km, rows, records) and lists them under "remaps" in qa.json, with the rows merged and the download's rows ("downloaded_rows"). Any other unknown code stays and fails the cell mark with its count. When the marks pass it writes data/gbif/<key>/_COMPLETE (rows, resolution, the zip's sha256), without which the loaders refuse the parts. --mark-complete writes that marker for an earlier ingest without ingesting again, once the parts are shown to hold the rows of qa.json, qa.json passes and every cell is in the grid of --resolution
----

== Cleaning the counts

[source,bash]
----
uv run python -I scripts/griis_codes.py --counts data/gbif/<key> [--out reference] [--overwrite] # freeze which country code each sub-national GRIIS list applies to (the US states, Svalbard, the French overseas places), from half A's counts, into reference/griis_uses_code-res<r>.csv (country, subdivision, code, sorted; tracked in git). A list is for the rows in its cells that carry its effective code: its own country code where the rows with that code are at least 10% of all the rows in its cells (the US states, and a small island such as Saba that shares a big cell with a bigger neighbour), otherwise the code with most rows among half A's rows in the list's cells (rows with no code do not count; a tie goes to the list's own country code, then to the lower code), so Svalbard, a list of NO whose records GBIF codes SJ, applies to SJ, and Reunion, a list of FR, to RE. The script prints every place with its code, the share of the rows in its cells that carry it, the list's own code's share and the next code, and warns of those under 80%. The resolution is the ingest's, from its _COMPLETE. Cleaning applies this table instead of reading the codes from whatever counts it is given, so that half A, a calibration subset and the later all-species run apply the same lists. A table that is already there is left alone if it is the same and refused if it differs or cannot be read, unless --overwrite says it is meant to. Half A only, no references (the grid and the admin-1 cells), about 8 GB, 15 seconds
uv run python -I scripts/clean_counts.py --counts data/gbif/<key> # the resolution is the ingest's, from its _COMPLETE (a --resolution given must agree with it); layers 1 to 5 on half A, once per WCVP mode (native_only, introduced, off), into results/clean/res<r>/<mode>/: presence, removed (every row taken out or moved, with its layer and rule), unplaced, the removal summaries, and suspect_cells.csv (the cells where layer 5 took far more of the species than it did next door, listed for inspection, nothing is removed for them); report.json holds the removals per layer and rule, layer 5 per rule in records, presences, species and cells with its suspect cells, the effect of each WCVP mode, the zero-area fold, the Caspian check, layer 4's species counts, the provisionally accepted twins and what the GRIIS lists hold (`griis_lists`). --griis-without-status says what layer 3 does with a GRIIS list that has no distribution table (250 of the 304 until they have an extended export): skip it (the default) or apply it name-only; run it once for each with its own --results to have both. The layer 5 thresholds are the defaults of `Settings`, which are setting 132 of the calibration (record share 2%, cell share 20%, rate factor 0.5%, group minimum 300; Markus, 2026-11-01), and report.json states them (`layer_5_thresholds`). Layer 3 reads the country code each sub-national list applies to from the frozen table of the resolution, `reference/griis_uses_code-res<r>.csv`, and the script refuses to start without it (run scripts/griis_codes.py); report.json has every place with its code and share (`list_codes`). About 20 GB at the peak at resolution 6 (1 minute), 17.8 GB and 131 s at resolution 7
uv run python -I scripts/griis_review.py --counts data/gbif/<key> --removed results/clean/res6/native_only/removed.parquet [--before <another run's removed.parquet>] # what GRIIS took out of half A, into results/clean/res<r>/griis_review/: griis_totals.json (rows, presences, records and species per GRIIS rule), with --before griis_change.csv (the 20 species whose GRIIS removals changed most between the two runs) and griis_neighbours.csv (the 20 largest GRIIS removals of species that also have clean, unlisted records in at least three neighbouring countries, two countries being neighbours where GBIF has rows of both in the same or adjacent cells: the likely feral or released forms of native species, for reading only, no rule changes; --min-neighbour-records N asks for N records in each neighbour). Half A only
----

== Calibrating the heuristics

[source,bash]
----
uv run python -I scripts/calibrate.py --counts data/gbif/<key> --resolution 6 # a dry run on half A (it never loads half B; the resolution is the ingest's, from its _COMPLETE, and --resolution must agree with it): the known cases of the design on the fully cleaned half A (those whose family is in half B are listed as waiting for step 9), then layers 1, 2 and 4 once and layer 5 at 144 settings (satellite record share 0.5, 1 and 2%, satellite cell share 2, 5, 10 and 20%, under-reported rate factor 0.5, 1, 1.5 and 2%, group minimum 300, 1,000 and 3,000), with layer 3 off, on the WCVP plants and the other species of their taxonomic groups; chooses the setting by a knee rule on a convex hull: the settings that lose at most 5% of the native presences over the whole run counting removals only (a presence a fold moved is not lost) are kept, the upper convex hull of their Pareto frontier on native presences lost and outside presences removed is walked from the lowest native loss, and a step is accepted while it costs at most 1 native presence for each extra outside presence removed (break-even); the last vertex accepted is chosen. It reports the chosen setting and the design's with layer 5 alone, the whole run counting everything and the whole run counting drops only; `report.json` also holds the whole Pareto frontier with an `on_hull` flag per setting (`knee_rule.frontier`, so that a dent of the frontier stays in sight), the hull with each step's marginal cost and whether it was accepted (`knee_rule.hull`), the step into the chosen setting and the step after it, both of the hull, and the reading and price the walk was made with and the choice of the rule of before, the most outside presences removed within 5% (`chosen_by_old_rule`), for comparison. Then the cross-check of layer 5 against GRIIS on half A's animals (layers 1, 2, 4 and 5, layer 3 off, at the chosen and the design setting): the share of the animal presences that GRIIS lists as introduced, from the lists with distributions, that layer 5 takes, against the share of all the other animal presences (reports only). --griis-without-status skip|apply is what layer 3 does with the lists that have no distribution table in the known cases (skip by default). The known cases run at the design's thresholds (`realms.calibrate.DESIGN`) whatever the defaults of `Settings` are, and layer 3 of the known cases and of the cross-check takes the country code each sub-national list applies to from the frozen table of the resolution (reference/griis_uses_code-res<r>.csv, scripts/griis_codes.py); the dry run refuses to start without it. Writes results/calibrate/res6/ (settings.csv with the 144 settings, regions.csv with the native loss per TDWG level 3 region, known_cases.json, griis_cross_check.json, calibrate.log, and report.json last, with the chosen setting, the knee walk and the ingest's marker). About 20 GB at the peak
uv run python -I scripts/calibrate.py --counts data/gbif/<key> --resolution 7 # the binding dry run at the analysis resolution, on half A, into results/calibrate/res7/ (the 144 settings took 18 minutes and peaked at 21.6 GB)
uv run python -I scripts/calibrate.py --counts data/gbif/<key> --resolution 7 --score-half-b --setting N # once, after Markus has read the dry run at 7 and chosen N (its number among the 144 in settings.csv, the knee rule's choice in report.json; it refuses a dry run whose chosen thresholds or whose settings.csv are not of the 144-setting grid, and records whether N is the dry run's choice but does not refuse another N): scores setting N on half B's calibration species (the plants and the other species of their taxonomic groups, which are not all plants), the one call before the freeze that opens half B (listed in DECISIONS.md). A run of its own: it loads the references and those species of half B and nothing else, and prints and saves rates and counts only. It refuses any resolution but 7, a missing or unfinished dry run at 7 (res7/report.json with its chosen setting, from the same ingest), and any earlier start: res*/held_out.started or res*/held_out.json under --results, or data/split/held_out-315557.started, whatever --results says. It writes both markers (the time, the commit, N and whether N is the dry run's choice) before it loads half B and res7/held_out.json after; copy the fixed marker's content into DECISIONS.md as soon as it is there. A run that failed after the load is for Markus to decide on, and there is no override flag
----

== Exploring on half A

[source,bash]
----
uv run python -I scripts/explore.py --counts data/gbif/<key> --wcvp-mode native_only [--rules-off griis ...] [--merge-duplicate-names] --configs explore/configs.toml --stage {clean,units,screen,select} [--only NAME ...] --workers 4 [--seed N] [--budget-gb 40] [--force] # the cached pipeline of M1, on half A only (the resolution is the ingest's, from its _COMPLETE; the frozen GRIIS code table of that resolution is read from reference/): each stage up to --stage runs unless its outputs exist with the hash of its inputs (cleaning settings, mode and rules switched off, the frozen code table, the counts' marker and the references' manifest; then the unit settings, then the configuration and the parameters, the seed among them), and --force runs the stage given again. A stage that writes its outputs again deletes the stamps of the stages that depend on it (cleaning those of the units and of every configuration, the units those of every configuration), and a change of what a stage does raises its METHOD_VERSION in realms/explore.py, which reruns it and what follows. Into results/explore/res<r>/<run>/, where <run> is the mode and the rules switched off (native_only, native_only-no-griis), with -merged-names after them under --merge-duplicate-names (a run of its own whose matrix merges the ids of a duplicate genus or family name, matrix.duplicate_names, and whose cleaned taxa keep the names that needs): cleaned/ (presence, removal summaries, and the major groups and the genus and family ids that the later stages use, so that they never load the references), units/ (members, presence, areas, adjacency, excluded, stats, removed_by_region.csv), and a directory for each configuration, <config>/ (<config>-s<N>/ under --seed N for an N other than 1, so that another seed never overwrites seed 1's), with the screen's files, and <config>/select/ with the select stage's. Each stage writes partition.parquet (unit, leaf, top), structure.json (modules, the largest module's share of units and of area, single-unit modules, levels, the units in no module with their count and a warning above 1%, and degenerate with its reason), candidates.parquet (unit, k, realm, sub_realm, sub_realm_of), parts.parquet (the realm of every part for every k, imputed parts flagged, the selected k marked) and log.json (time and peak memory, and each worker's peak); the screen adds screen.csv, the select stage selection.csv and selected.json. Screen is Infomap at the configuration's trials_screen and n_null_screen null maps; select is the design's 10 trials, 20 bootstraps of 3 trials and 99 null maps, then select_level. A degenerate clustering is written to structure.json, never raised. The parts that the network units leave out are in no network, map or score, and get their realm from impute in the outputs only. Cleaning and the units each run in a child process (their peaks are reported; cleaning peaked at 17.9 to 24.1 GB on the runs of M1 at resolution 7, the units at about 6 GB); --workers is the most the bootstrap and the null maps may start, and fewer start if they would not fit in --budget-gb (default 40) next to the parent, from the peak the first two tasks measure. explore/configs.toml holds the named Infomap options (the ten of the scale sweep: default, mt095 to mt075, variable, regularized, entropy, recurse50) and the screen's two figures
uv run python -I scripts/migrate_select.py [--results results/explore] # once, for the runs made before select had a directory of its own: moves each configuration's select result (its map files, selection.csv, selected.json, stamp and log entry) into <config>/select/, deletes the screen's stamp, since select had overwritten the screen's map files, and writes MIGRATED.txt; screen.csv stays. A configuration already moved, or with a screen only, is left alone, so it can run again
uv run python -I scripts/circularity.py --counts data/gbif/<key> [--config mt090] [--runs off introduced native_only ...] [--rotations 99] # the circularity gate on half A: reads the current select result of one configuration of each cleaning run (explore.read_selected, which refuses one that is not current), and writes to results/explore/res<r>/circularity/ runs.csv (each run's selected k, stability, parts and land and sea boundary km), pairs.csv (the V-measure by part between every pair of runs at their selected and their common k, and the boundary km that moves), moves.csv (the moved land boundary by TDWG level 1 region), near_by_region.csv (the share of land edges and boundaries near TDWG edges, by region), gate.csv (boundaries.gate, the first run the base and every other a mode, against TDWG level 3 regions rotated 99 times, read with the rotations kept within 0.5 of the regions' boundary over land and with all of them) and run.log with the headline mode. The grid, the land and the regions come from the references' manifest. About 3 minutes, a few GB
uv run python -I scripts/crosscheck.py --counts data/gbif/<key> --parts betasim names [--run native_only] [--config mt090] [--seeds 1 2 3] [--ks 5 12] # the cross-checks of the headline map, into results/explore/res<r>/crosscheck/ (run.log is appended to): betasim, a beta-sim consensus (Ward and UPGMA, 20 shuffles of the cell order, each of --seeds) on the units and matrix the select stage scored, against Infomap's map at each k (betasim_v.csv, betasim_seeds.csv, betasim_area.csv with the share of area on which they agree, betasim_labels.parquet; a pair of seeds below --seed-floor runs again with --more-shuffles); names, the same configuration of the run that merges duplicate names (--merged, default <run>-merged-names) against the run on ids (names_v.csv, names_selection.csv, names_duplicates.csv). Both read select results with explore.read_selected. Betasim takes about 12 minutes and 4.5 GB
uv run python -I scripts/review_maps.py --counts data/gbif/<key> [--run native_only] [--base off] [--config mt090] [--no-floor-ks 19 30] # the review package of the headline map, into results/explore/res<r>/review/: maps of the selected k and the candidates either side (k<k>.png and .gpkg, sub-realms outlined, imputed parts hatched, a realm's colour kept across them), maps without the size floor at --no-floor-ks for M4 only (k<k>-no-floor.png and .gpkg, no_floor_parts.parquet, no_floor_units.parquet, no_floor_realms.csv), a panel per realm (realm-<r>-k<k>.png), the land boundary against --base in one TDWG level 1 region (boundary-<region>-k<k>.png and .csv), and realms-k<k>.csv, sub_realms-k<k>.csv, summary.csv and tables.md, the realms' areas of parts (imputed included) and of units, their endemic species and sub-realms. Reads the current select results with explore.read_selected. About 4 minutes, under 3 GB
uv run python -I scripts/seeds.py --counts data/gbif/<key> [--run native_only] [--configs-to-judge default mt075 mt080 ...] [--seeds 1 2 3 4 5] [--out DIR] # stability over seeds (DECISIONS, 2026-11-03): reads the current select result of every configuration at every seed (explore.read_selected; scripts/explore.py --seed N writes <config>-s<N>/) and fails naming any that is missing, then writes to results/explore/res<r>/<run>/seeds/ per_seed.csv, across.csv (per configuration and k, the median stability over the seeds, 0 where a seed has no map, and the median excess), choice.json (the select rule over the pooled medians: the configuration and k, or the most stable map flagged as falling short) and agreement.csv (seed 1's map of the choice against the other seeds' at that k). Seconds, no counts loaded
----

== Layout

`src/realms/`:: The analysis package.
`scripts/`:: Runs that produce results.
`explore/`:: `configs.toml`, the named Infomap configurations of `scripts/explore.py`, tracked in git.
`reference/`:: Frozen decisions of the method, tracked in git: `griis_uses_code-res<r>.csv`, the country code each sub-national GRIIS list applies to.
`queries/`:: The generated occurrence queries, and the SQL of the Denmark column check.
`tests/`:: Unit tests.
`data/`, `results/`:: Downloads and outputs. Neither is committed.
